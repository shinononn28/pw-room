# プリンセスウイング卓（通信版サーバー）

Render の Web Service で動く部屋サーバーです。画面（public/index.html）もこのサーバーが配ります。
部屋の状態とログは Firestore に保存されるので、Render が停止・再起動しても続きから遊べます。

## 1. Firebase 側の準備（ブラウザだけで完結）

1. 日程あわせで使っている Firebase プロジェクトを開く（別プロジェクトでも可）
2. ⚙「プロジェクトの設定」→「サービス アカウント」→「新しい秘密鍵を生成」
   - JSON ファイルがダウンロードされます。**これはパスワードと同じなので、GitHub には絶対に上げないでください**
3. Firestore のルールの変更は不要です（サーバーは管理者権限で読み書きします）

## 2. GitHub に置く

このフォルダ（pw-server）の中身をリポジトリにアップロードします。
`node_modules` と、ダウンロードした秘密鍵の JSON は含めないでください（.gitignore で除外済み）。

## 3. Render で Web Service を作る

- New → **Web Service** → リポジトリを選ぶ
- Runtime：Node
- Build Command：`npm install`
- Start Command：`node server.js`
- Instance Type：Free でも動きます

**Environment（環境変数）**

| 名前 | 中身 |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | ダウンロードした秘密鍵 JSON の中身を**まるごと**貼る |
| `GROUP_ID` | 保存場所の名前（好きな英数字。例：`otherchat-a`） |
| `FIRESTORE_DATABASE_ID` | データベースを名前付きで作った場合だけ、その名前 |

デプロイが終わると `https://＜サービス名＞.onrender.com` で開けます。

## 4. 遊び方

1. GM がトップページで「部屋を作る」→ そのブラウザに GM キーが保存され、GM 席で入ります
2. 部屋の上部の「招待リンク」をコピーして、オプチャで PL に送ります
3. PL はリンクを開くと観戦で入ります。「キャラを取り込む」で自分のキャラを読み込むと、そのキャラの席に座り、そのブラウザに**席の鍵**が保存されます
4. 次からは、同じブラウザで開けば自動で前回の席に戻ります
5. PL が別の端末（スマホなど）で入るときは、キャラの詳細にある **席のリンク** をその端末で開きます
6. GM が別の端末から入るときは、「部屋の設定」にある **GM 用リンク** を使います（PL には送らないでください）
7. PL が端末をなくしたなどのときは、GM がキャラの詳細で **席の鍵を作り直す** と、新しい席のリンクがコピーされます。古い鍵は使えなくなります

## そのほかの機能

- **プレイヤー名**：初めて部屋に入るとき、そのブラウザで1回だけ名前を聞きます（メニューから変更可）。秘匿タブの参加者はこの名前（プレイヤー単位）で選びます
- **リンク**：部屋の上部「リンク」に、招待リンク・自分の席のリンク・GM用リンク・GMのキャラをPLに渡すリンクがまとまっています
- **BGM**：GMが音声ファイル（20MBまで）を選ぶと全員に流れます。サーバーのメモリに一時的に置くだけで、保存はしません（停止・再起動で消えます）。音量とミュートは各自で設定できます

## 知っておいてほしいこと

- Render の無料プランは、15 分ほどアクセスがないと停止します。次に開いたときは、起き上がるまで 30 秒〜1 分ほど待ちます
- 停止の直前に部屋の状態を保存します。ログは発言のたびに保存しています
- 山札の並びと GM の手札はサーバーの中だけにあり、PL のブラウザには枚数しか送りません
- 席の鍵を持っていない人は、そのキャラの席に座れません（観戦になります）
- 鍵の導入前に作ったキャラは、最初に座った人に鍵が発行されます
- 環境変数 `FIREBASE_SERVICE_ACCOUNT` を設定しないと、メモリ上だけで動きます（再起動で消えます。動作確認用）

## ローカルで試す

```
npm install
node server.js        # http://localhost:10000
```
